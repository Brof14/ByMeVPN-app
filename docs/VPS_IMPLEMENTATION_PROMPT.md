# Задание для ИИ с доступом к VPS ByMeVPN

Ты — старший backend/SRE разработчик. Сначала изучи развёрнутую систему и репозиторий ByMeVPN_bot, затем внеси и проверь необходимые изменения. Не запрашивай и не выводи пароли, приватные ключи, токены пользователей и ссылки подписок в чат, логи, коммиты или отчёты. Не удаляй существующие базы, настройки и ключи: перед миграциями сделай проверяемую резервную копию и план отката. Покажи доказательства тестов без секретов. Не объявляй оплату или авторизацию рабочей без сквозной проверки.

## 1. Инвентаризация и HTTPS

Определи фактические домены, конфигурацию reverse proxy, API, bot, 3x-ui, вебхуки и данные, действующие тарифы, OAuth и YooKassa. Не считай значения из кода актуальными без сверки с работающей системой. Подними проверенный HTTPS для API и подписок с валидным сертификатом, закрыв прямой публичный доступ к незащищённому API. Согласуй точный публичный `BASE_URL` для Android и проверь корректные TLS-сертификат, DNS, таймауты, отсутствие перенаправлений на HTTP и обновление сертификата. Ключи храни в серверном secret store или переменных окружения.

## 2. Google Sign-In — критическая безопасность

Текущий `api_router.py` только декодирует payload Google ID-токена и использует email без проверки подписи; такой токен можно подделать. До исправления отключи этот путь. Реализуй проверку подписи через опубликованные Google ключи и доверенную библиотеку; проверь `iss`, точный `aud` разрешённого Web Client ID, `exp`, `iat`, `email_verified` при использовании email и nonce по выбранной модели. Идентифицируй пользователя по стабильному Google `sub`, а не по email или обрезанному MD5. Запрети небезопасное слияние с существующим аккаунтом без доказательства владения обоими способами входа. Настрой Android OAuth client для release package и настоящих SHA-1/SHA-256 подписей, включая Play App Signing, и Web client для `serverClientId`. Проверь действительный, просроченный, поддельный токен, неправильный issuer/audience и повторный nonce; проверь вход на реальном устройстве.

## 3. Telegram — вход без ручного копирования

Реализуй короткоживущую одноразовую сессию на сервере с криптографически случайным state, ограничением частоты, TTL и атомарным погашением. Приложение создаёт сессию, открывает официальную ссылку бота; бот явно показывает пользователя и подтверждение входа, затем авторизует сессию и показывает кнопку «Вернуться в ByMeVPN» с проверенным Android App Link/резервным deep link. Самовольный возврат без действия пользователя не гарантируется ограничениями Android/Telegram. При возврате приложение проверяет state и однократно обменивает код на токены по HTTPS; polling может быть резервным вариантом. Не передавай access/refresh токены в URL, не используй перехватываемый deep link как единственное доказательство владения сессией. Сессии должны работать при нескольких процессах и перезапуске (хранилище с TTL), а не только в памяти Python. Защити от replay, подмены state, открытых редиректов и связывания чужого аккаунта; тесты на два устройства, отмену, истечение и повторное использование.

## 4. ЮKassa и Google Play

Подготовь реальные server-side API для создания заказа и одноразового платёжного токена мобильного SDK ЮKassa, используя опубликованный SDK и серверный API; секретный ключ магазина остаётся только на сервере. Клиент получает публичный идентификатор магазина и вводит платёжные данные в SDK, сервер создаёт платёж с idempotency key, проверяет его статус непосредственно у ЮKassa и обрабатывает повторные/задержанные вебхуки. Не выдавай подписку по deep link или неподтверждённому webhook. Обеспечь резервное сверение статусов, корреляцию с пользователем/заказом, авторизацию, возвраты и журнал аудита без секретов. Для 3-D Secure и банковских приложений может понадобиться системный экран подтверждения: не обещай, что переходов не будет.

Реализуй серверное состояние способа оплаты и автопродления, включая проверенный payment_method_id, согласие на сохранение, признак сохранения, замаскированные реквизиты, статус, сумму и дату следующего платежа. Клиент не видит реальные номера карт. Добавь безопасные API для включения/отключения автопродления и удаления сохранённого метода; идемпотентность и тесты задержек и повторов обязательны. Тарифы и валюта приходят с сервера. Прогони тестовые платежи и возвраты в тестовом магазине, затем согласуй реальный запуск.

Google Play: проверь актуальную Payments policy для выбранных стран и дистрибутива. Для цифровой VPN-подписки Google Play Billing обычно обязателен, если не применимо явно разрешённое исключение или программа. Не обещай, что обычная встроенная ЮKassa разрешена в Play. При необходимости раздели Play и direct APK по billing provider и реализуй проверку покупок и подписок на backend.

## 5. Реферальная программа и помощь

В текущем боте присутствуют бонусы +15 дней за регистрацию приглашённого и +30 дней за первую подходящую платную подписку. Сверь реальные правила и единожды обрабатываемые события в production. Предоставь авторизованные API для получения персональной ссылки/кода и статистики, применения кода при регистрации и истории начислений. Начисление только на сервере, атомарно, с антифродом, идемпотентностью и тестами самоприглашения/гонок. Добавь поддержку обращений об ошибках и улучшениях: за подтверждённые ошибки и принятые предложения начисляются дополнительные дни по решению команды. Не публикуй доступные для подделки клиентские подтверждения.

## 6. Запуск и приёмка

Проверь права VPN, приватность, реальную политику конфиденциальности, data safety и актуальные требования Google Play. Проверь, что карты, устройства, подписка и статус отображаются только из подтверждённого источника; протухшие данные помечены. Ротация старой VPN-конфигурации, которая присутствовала в Git-истории, обязательна после сверки владельца и влияния на пользователей. Проведи тесты Android + сервер на реальных аккаунтах без публикации секретов: VLESS Reality/TLS, Hysteria, XHTTP, DNS, IPv4/IPv6, смена сети, падение сервера, завершение и отзыв разрешения, Google/Telegram, оплата, повторный webhook, карточный статус, рефералы, восстановление после рестарта. Отчитай отдельно о сделанном, результатах, неработающем и необходимых доступах; не заявляй готовность Google Play до выполнения всех условий.
