# ByMeVPN — дизайн-система V2 и план внедрения

**Дата анализа:** 27 октября 2026 г.  
**Исходники:** [Android-приложение](https://github.com/Brof14/ByMeVPN-app) · [Telegram-бот](https://github.com/Brof14/ByMeVPN_bot)  
**Формат:** 16 PNG-макетов + исходный HTML/CSS + руководство.

## 1. Продуктовое решение

**Цель:** приложение для массового пользователя, не панель администрирования VPN. На главном экране оставляем только состояние соединения, главный переключатель и — исключительно при активной подписке — доступный сервер. Оплату и управление переносим в понятные отдельные сценарии.

Визуальная система: почти чёрный фон, графитовые поверхности, тонкие матовые границы, один ясный мятно-зелёный CTA, белая типографика, спокойные интервалы. Киберпанк, глянцевые 3D-иконки, чрезмерное свечение, плашки «ПРЕМИУМ», значки подарков, бесполезные подписи и длинные технические объяснения убраны. Градиент щита ByMeVPN — брендовый акцент, не элемент для каждого блока.

Слоган: **«Скорость. Свобода. Простота.»**

## 2. Продуктовые константы из Telegram-бота

Источник: [`constants.py`](https://github.com/Brof14/ByMeVPN_bot/blob/main/constants.py) и [`handlers/start.py`](https://github.com/Brof14/ByMeVPN_bot/blob/main/handlers/start.py).

| Оплаченный срок | Фактический срок | 2 устройства | 5 устройств | 10 устройств |
|---|---:|---:|---:|---:|
| 1 мес. | 30 дней | 89 ₽ | 109 ₽ | 129 ₽ |
| 3 мес. + 1 в подарок | 120 дней | 316 ₽ | 396 ₽ | 476 ₽ |
| 6 мес. + 2 в подарок | 240 дней | 552 ₽ | 712 ₽ | 872 ₽ |
| 12 мес. + 3 в подарок | 450 дней | 885 ₽ | 1 185 ₽ | 1 485 ₽ |

Формула: `total = (base_monthly_price[paid_months] + device_extra[devices]) × (access_days[paid_months] / 30)`; оплаченное число месяцев и число месяцев фактического доступа различаются. Для цены 59 ₽/месяц покупатель платит 885 ₽ **сразу за 15 месяцев**, а не 59 ₽ каждый месяц. Любой будущий API должен возвращать сам срок, объём права и полную сумму с источника сервера.

**Пробный платный доступ**: 1 ₽ сегодня на 3 дня, **до 2 устройств**. Если сохранён способ оплаты, затем 89 ₽/30 дней с автопродлением. Если способ не сохранён, автоматического платежа нет. Явно раскрывать условия **до подтверждения оплаты**, предоставлять доступный путь отключения продления. Пробный тариф предназначен для однократного использования. Платёжная схема должна согласовываться с актуальными правилами платежного провайдера и применимым законодательством.

## 3. Подтверждённые рассогласования и опасные места в коде

### P0 — до выпуска платной версии

1. **Бесплатные 3 дня в приложении**. [`PaywallSheet.kt`](https://github.com/Brof14/ByMeVPN-app/blob/main/app/src/main/kotlin/com/example/bymevpn/components/PaywallSheet.kt) вызывает бесплатную активацию; бот продаёт пробный доступ за 1 ₽. Удалить бесплатный сценарий, заменить на реальную серверную оплату.
2. **Клиент может локально признать подписку оплаченной.** [`YooKassaPaymentHandler.kt`](https://github.com/Brof14/ByMeVPN-app/blob/main/app/src/main/kotlin/com/example/bymevpn/data/payment/YooKassaPaymentHandler.kt) сохраняет ожидающую оплату, а `checkAndCompletePendingPayment` вызывает `confirmPayment` и `activatePaidSubscription` без доказанного завершения платёжного процесса со стороны сервера. Этот локальный статус нельзя использовать как истинное платёжное право. Разблокировка только после серверного webhook + `GET /subscription/status`.
3. **Локальный fallback пробного доступа.** [`SubscriptionManager.kt`](https://github.com/Brof14/ByMeVPN-app/blob/main/app/src/main/kotlin/com/example/bymevpn/data/subscription/SubscriptionManager.kt) при ошибке вызова `activateTrial()` создаёт локальный активный пробный период. Убрать. Ошибка сервера → состояние «Не удалось проверить доступ», а не открытие оплаченных функций.
4. **Зашитые тестовые конфигурации серверов и приватно значимые поля.** Тот же `SubscriptionManager.kt` содержит `ensureDefaultServerConfigs()` с IP, UUID, Reality-полями и fallback-узлами. Заменить на реальные entitlement-bound данные по авторизованному серверному API. Нельзя выводить тестовые страны, пинги и подключения пользователю.
5. **Публичный ключ для проверки прав — placeholder.** [`ApiConfig.kt`](https://github.com/Brof14/ByMeVPN-app/blob/main/app/src/main/kotlin/com/example/bymevpn/data/api/ApiConfig.kt) содержит очевидную подставную строку ES256. Серверная верификация и защищённая синхронизация entitlement обязательны.
6. **Отсутствие подтверждённого единого API.** Android ожидает `/auth/*`, `/subscription/*`, `/plans`, `/servers`, `/vpn/session`, `/devices` по `https://api.parahin.space:8443/api/v1`; в проверенном репозитории бота `webhook.py` реализованы `/healthz` и платежные/Telegram webhook. Это **не доказывает**, что внешний API отсутствует (он может жить в отдельном сервисе), но его контракт и реальное развёртывание необходимо проверить до интеграции.

### P1 — достоверность интерфейса

7. В [`HomeScreen.kt`](https://github.com/Brof14/ByMeVPN-app/blob/main/app/src/main/kotlin/com/example/bymevpn/screens/HomeScreen.kt) есть fallback-дата окончания `24 ноября 2026`, а в [`AccountScreen.kt`](https://github.com/Brof14/ByMeVPN-app/blob/main/app/src/main/kotlin/com/example/bymevpn/screens/AccountScreen.kt) — `29` дней и количество устройств при неизвестном статусе. Никогда не показывать эти значения, если API их не подтвердил. Правильный пустой стейт: «Проверяем подписку» или «Не удалось обновить данные».
8. В paywall зашиты 149/399/699/1199 ₽ и 5 устройств, в боте 89/316/552/885 ₽ для 2 устройств (и отдельные значения 5/10). Полный отказ от client-side hardcoded прайсов: [`/plans`](https://github.com/Brof14/ByMeVPN-app/blob/main/app/src/main/kotlin/com/example/bymevpn/data/api/ByMeApiClient.kt) должен отдавать клиенту реальные офферы.
9. Технический текст ошибки (`infra/conf/serial`, JSON parse, VLESS / routing configuration) нельзя показывать пользователю. Логировать внутренний код ошибки, показывать короткую локализованную причину и действие «Повторить»/«Написать в поддержку».
10. Не заявлять «до 1 Гбит/с», «всегда обход блокировок», «Zero Logs» и «блокируем всю рекламу» без проверяемых оснований. В UI использовать конкретные и проверенные свойства услуги.
11. Проверять `status`, срок entitlement, ограничения устройств, отзыв доступа, синхронизацию, VPN connectivity отдельно. Факт запуска VPN-процесса ≠ доказательство успешного защищённого соединения.

## 4. Новая структура приложения

```text
Вход / Регистрация
    ↓
Главная
 ├── НЕТ ДОСТУПА → «3 дня за 1 ₽» / «Тарифы»
 ├── ДОСТУП ЕСТЬ + VPN OFF → «Подключить» → «Серверы»
 ├── ДОСТУП ЕСТЬ + VPN ON → «Отключить» → «Серверы»
 └── ОШИБКА → «Повторить» / «Помощь»

Аккаунт
 ├── Состояние подписки / Продление
 ├── Устройства
 ├── Автопродление (с реальными условиями)
 ├── Настройки аккаунта
 └── Помощь

Настройки
 ├── Подключение
 ├── Комфорт
 ├── Дополнительно (Kill Switch, DNS, исключения)
 └── Язык

Помощь
 ├── Написать в поддержку
 ├── Ответы на вопросы
 ├── Новости
 └── Информация и документы
```

Нижняя навигация: **Главная / Настройки / Аккаунт**. Не дублировать «Настройки» и «Аккаунт» отдельными большими страницами, не занимать основной экран второстепенными возможностями.

### Машина состояний (обязательно реализовать в Android)

```kotlin
sealed interface AccessUiState {
    data object Loading : AccessUiState
    data object NoPlan : AccessUiState
    data object Expired : AccessUiState
    data class Active(val expiresAt: Instant, val maxDevices: Int) : AccessUiState
    data class Trial(val expiresAt: Instant, val maxDevices: Int) : AccessUiState
    data class Unavailable(val reason: String) : AccessUiState
}

sealed interface TunnelUiState {
    data object Disconnected : TunnelUiState
    data object Connecting : TunnelUiState
    data object Connected : TunnelUiState
    data class Failed(val category: ConnectionError) : TunnelUiState
}
```

Правила:
- Серверы выводятся **только если** сервер подтверждает активное право и вернул список доступных узлов. Данные из прошлого сеанса могут использоваться только как осторожно маркированный кэш, не для выдачи ложного успеха.
- В `Loading` показывать загрузку / skeleton, а не выдуманный тариф.
- В `NoPlan` / `Expired` пользователь видит оформление, а не кнопку VPN и серверы.
- В `Failed` отображать действие, соответствующее причине: интернет, сервер, повреждённая конфигурация, отсутствие оплаты.
- Никогда не показывать «подключено» до успешного запуска и подтверждения корректной работы туннеля.
- `autoRenew=true` только после подтверждения сохранённого способа оплаты / серверного статуса. Для `false` показывать «Выключено», а не обещание списаний.
- Цена, количество устройств, окончание, отмена подписки должны быть синхронны между ботом, приложением, платежным провайдером.

## 6. Jetpack Compose — визуальные токены

В репозитории основной актуальный Android-клиент — **Jetpack Compose** (`app/src/main/kotlin/...`), при этом присутствуют старые/параллельные Flutter и Android-модули. Реализацию актуального клиента необходимо вести в одном выбранном стеке, не менять сразу несвязанные демо-подпроекты.

| Токен | Значение |
|---|---|
| Фон | `#080E10` |
| Поверхность | `#111A1D` |
| Поверхность, акцент | `#142A25` |
| Границы | `#203137` |
| Основной текст | `#EEF4F4` |
| Вторичный текст | `#91A6A5` |
| Основной акцент | `#3CDEAC` |
| Основная CTA | градиент `#38EFB6 → #48D8B7` |
| Ошибка | приглушённый красный **только по делу** |
| Внешний отступ | 26–28 dp |
| Радиусы основных карточек | 18–21 dp |
| Радиус кнопок | 15–17 dp |
| Минимальная область нажатия | 48 × 48 dp |
| Заголовок страницы | 27 sp, Semibold |
| Основной заголовок | 25–30 sp, Semibold |
| Основной текст | 14–16 sp (увеличить относительно уплотнённых вариантов макета) |
| Вторичный текст | 12–13 sp |

**Важно:** PNG — визуальные спецификации, а не изображения, которые нужно ставить фоном всего экрана. Собрать нативно из Compose-компонентов: корректные состояния, размер шрифтов, TalkBack, масштабирование, небольшие устройства, системная клавиатура и анимации. HTML/CSS — редактируемый исходник визуального дизайна, не клиентский VPN-код.

## 7. План выполнения

1. **P0.** Убрать фальшивые триалы и локальную выдачу оплаченного entitlement, тестовые серверы и фиктивные статусы. Согласовать с действительным backend API. Проверить платёжный webhook, возврат в приложение, idempotency, отключение автопродления.
2. **P1.** Подключить `/plans` с 2/5/10 устройствами и подарочными сроками, серверное состояние подписки и корректные варианты главной страницы.
3. **P1.** Переписать paywall/тарифы/аккаунт, спрятать legacy-key management из обычного UX, оставить безопасные маршруты восстановления подписки для мигрировавших пользователей (при необходимости в поддержке).
4. **P2.** Реализовать компоненты дизайн-системы (`ByMeButton`, `ByMeCard`, `AccessStatus`, `ServerRow`, `SettingsRow`), тёмную тему и единые токены.
5. **P2.** Проверить реальные устройства: маленькие экраны, большой системный шрифт, состояние без сети, медленный API, просроченный токен, удалённый узел, неудачный платёж, незавершённая оплата, отмена подписки.
6. **P2.** Провести usability-тест с 5–8 людьми, не знающими VPN-терминов. Признак успеха: вход → понимание условий → активация → подключение без дополнительных пояснений.
